# Method, coordinates and limits / 方法与局限

更新：2026-11-16。

## 来源与时间

原始观察、回忆、公开报道、后期转写、推断与模拟分别记录。录音日期优先原始元数据并结合笔记，不把DOCX创建日、公众号发布日期、截图文件名或本轮读取日当作现场日。转写错词保留原串、建议串和校订依据；未听原音尤其不确定方言转写不作正式地名依据。

同名不等于同一地点，区域标签不等于建筑入口。只在实体身份、功能、空间和时间分别有证据后再决定合并。重复名称只生成复核候选，不自动删除数据。已有示意图未经配准，不推定方向、距离、边界、住宅与田地范围或书苑落点。

目前对书苑只有一个可直接引用的公开报道来源，不声称已完成多来源事实核验。材料恢复和多个网页命中也不构成独立证据数量。因果、水文历史和行政隶属均保留待核。

## 坐标参考系

当前坐标全部为空，未完成坐标转换、配准、叠加误差评估或精度测量。因此CRS差异是后续风险，**尚无本项目中已经测得的偏移量**。

- GeoJSON按 [RFC 7946 §4](https://datatracker.ietf.org/doc/html/rfc7946#section-4) 使用WGS84经纬度，点顺序为`[longitude, latitude]`；不能仅改标签就把GCJ-02数据当WGS84。
- 高德坐标转换文档说明非高德坐标需按来源转换。应先记录来源坐标制式；GCJ-02与WGS84不能直接混用。参见 [高德坐标转换](https://lbs.amap.com/api/webservice/guide/api/convert) 和 [高德对GCJ-02与WGS84的说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)（2026-11-16查阅）。本轮没有调用坐标转换API。
- Leaflet的数据接口和底图投影是不同问题：以后应按接口顺序传经纬度；渲染投影不能修复来源坐标偏移。接入前再核对所用版本文档。
- 保存原坐标、原CRS、来源日期、转换服务/版本、转换时间和人工对照结果；不覆盖原始值，不使用无出处的网上逆变换来宣称测绘精度。坐标小数位数不等于准确度。

恢复的两张截图缺完整网页链接、坐标网格、图层署名与影像采集日期。即使历史用户说来自OpenStreetMap，也不能认定影像或地形渲染同属OSM许可。没有可靠精度依据，不写“米级准确”。

## 许可与隐私

OSM数据许可、渲染图层、卫星影像、截图和网页文字分别审核。参考 [OSM copyright](https://www.openstreetmap.org/copyright)、[OSMF attribution](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)、[tile usage policy](https://operations.osmfoundation.org/policies/tiles/)（2026-11-16读取相关页面）。将来使用标准瓦片需可见署名、遵守缓存和请求要求，不批量抓取/预取，不以OSM数据许可替代第三方影像许可。

当前不复制新闻全文、配图或旧截图；只存自写简短摘要及链接。手绘作者、是否儿童作品、创作日期和再使用授权未知；仅“已在公众号出现”不等于可用于求职作品集。原图中私人地点和可识别信息先人工审查与去标识化，未确认前只列材料元数据。

不导入儿童身份、住宅精确点、个人路线、未经同意的访谈全文。访问权限不能只靠前端隐藏；公开仓库中不存在的私有资料才不会被一同下载。

## 推理与能力边界

本轮AI参与资料查找、结构、草拟、英文和代码。个人经历来自用户自述，具体独立贡献待确认。不会把推荐安装的软件或AI写的代码变成用户已经掌握的技能。自动校验只检查契约与结构，无法证明地点真伪、当前营业、作者授权、空间精度或评分符合招聘方标准。
